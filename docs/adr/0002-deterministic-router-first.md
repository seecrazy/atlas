# ADR 0002：先实现确定性 Router，再引入 LLM Router

## 状态

已采纳

## 背景

四层角色 Agent 的价值依赖请求能否被送到正确粒度。直接使用 LLM 分类虽然灵活，但在索引覆盖不足时容易产生看似合理但不可验证的路由，也会增加成本和回归风险。

## 决策

Phase 4 先实现基于关键词规则和索引信号的确定性 Router，并通过 MCP 工具 `atlas_route` 暴露。

## 理由

1. 输出 schema 稳定，便于测试。
2. 不调用模型，延迟和成本低。
3. 路由信号可审计，方便统计误路由率。
4. 在确定性 Router 达到可接受准确率后，再让 LLM 只处理兜底和复杂歧义。
5. Agent 权限边界不被 Router 的自然语言判断放宽。

## 后果

### 正面

- 路由行为可复现。
- 可以建立冻结路由验证集。
- 索引质量不足时能显式返回 warning。

### 负面

- 对复杂自然语言表达较弱。
- 需要维护中英文规则。

## 重新评估条件

出现以下情况时重新评估：

1. 真实验证集显示规则 Router 误路由率过高。
2. 用户问题大量依赖语义摘要或业务术语。
3. 需要多步意图拆解和动态子任务编排。
