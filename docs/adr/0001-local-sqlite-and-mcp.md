# ADR 0001：使用本地 SQLite 与 MCP stdio 作为第一运行面

## 状态

已采纳

## 背景

ATLAS 的目标项目通常包含多个仓库和大量文件。方案候选包括嵌入式 SQLite、外部图数据库、独立索引服务和远端服务。MCP 接入方式包括 stdio 和 HTTP。

## 决策

Phase 1 使用本地 SQLite WAL 数据库和 stdio MCP Server。

## 理由

1. 无外部服务、Docker 或守护进程依赖，最小可运行面简单。
2. SQLite 足以承载符号、引用、记忆和审计记录。
3. MCP stdio 可以直接接入 Codex CLI、Claude Code、Cursor 等客户端。
4. scope token 可以在 MCP Server 内部统一校验，不依赖客户端权限模型。
5. 本地数据库便于审计和回滚。

## 后果

### 正面

- 项目首次可用时间最短。
- 调试成本低。
- 不需要中心化基础设施。

### 负面

- 不适合多人共享同一索引。
- 复杂图查询表达力弱于图数据库。
- 跨机器实时协同能力有限。

## 重新评估条件

出现以下情况时重新评估：

1. 多人/多机需要共享索引。
2. 跨仓影响查询超过 SQLite 性能预算。
3. 需要长时间运行的大规模增量守护。
