# ADR 0004：Kernel、四层 Agent 与审批补丁

## 状态

已采纳

## 背景

仅靠提示词无法保证 Agent 不越权。代码修改、外部发送、权限变更和运行时自我修改属于高风险动作，必须由内核强制约束。

## 决策

1. 所有 Agent 运行必须使用 Budget。
2. Developer Agent 读取物理文件必须持有服务端 scope token。
3. finding evidence 必须通过 verifier。
4. `apply_patch` 只能在人类审批后执行。
5. 可选 LLM Provider 通过环境变量配置；失败时退回确定性 Worker。
6. Evolution 只能离线评分，不直接修改运行时规则。

## 理由

1. 权限边界可机械验证。
2. Agent 行为可审计。
3. 补丁应用前可测试。
4. LLM 失败不会导致不可用。
5. 进化不会绕过审批。

## 后果

### 正面

- 安全模型与索引能力解耦。
- 可逐步替换 Worker。
- 支持无 LLM 环境。

### 负面

- 无 LLM 时结论粒度有限。
- 补丁仍需人工审批。
- 进化提升流程尚未自动化。

## 重新评估条件

1. LLM Worker 通过真实项目评估。
2. 审批策略支持自动化低风险合并。
3. 需要多用户远程部署。
